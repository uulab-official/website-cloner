## 변경 범위

기준 main은 `efdc068c4909c85ba920308f3af39c2d51d73c9e`, 최종 실행 검증한 구현은 `b38b407bb6e3a2979a2dc4aa29e2f31f732dfa96`다. 이후 검증 기록 커밋은 문서만 변경하며 이 구현을 바꾸지 않는다.

`npm run prepare:clone`은 기존 init → source capture → observe를 연결해 **원본 증거가 있는 구현 시작점**을 만든다. 원본·예정 구현 URL, 새 출력 경로를 받아 suite와 기본 기록, 원본 캡처, 관찰 보고서, START-HERE.md, index.html, 단계별 preparation.json과 로그를 생성한다. 구현 서버를 실행하거나 target을 직접 방문하지 않는다. 앱 자동 생성·자산 다운로드·권리 승인·원본/구현 비교 명령이 아니다. [사용법](prepare-clone.md)을 참고한다.

초기화한 다섯 파일은 그대로 유지하고 관찰 자산 후보와 편집할 권리 기록을 분리한다. `prepared`여도 implementation은 not_started, functionalParity는 not_verified, visualComparison은 not_performed, reviewRequired는 true다. 요청과 다른 원본·엔진·화면 크기·상태·테마와 누락 증거를 거부하며 child exit 0만 믿지 않는다. 실패 후 파일을 지우거나 덮어쓰지 않는다. capture 로그는 스트림마다 마지막 12,000자다.

명령은 npm의 자동 lifecycle인 prepare와 별개인 prepare:clone이며 기존 예제·스킬·수집기·비교 계산·package-lock.json은 변경하지 않았다. 새 의존성은 없다.
