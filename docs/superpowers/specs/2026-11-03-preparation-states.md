# Stateful source preparation

Extend prepare:clone, not the capture engine, with explicit state, preferred color scheme, click/scroll actions and retained scrolling. Preserve the default workflow and dependencies. Store validated action snapshots inside the newly created workspace; suite.json must reference those relative paths so later verify:suite uses the same state. A target-specific action file may override the shared source actions but is never executed during preparation. All observations remain unverified for functional parity, backend behavior and reuse rights.

Validate before writes/processes, including dry-run. Limit files to 100,000 bytes, actions to 50 and selectors to 2,000 characters; allow only click/scroll with exactly type/selector. Reject control characters, invalid state/scheme and symbolic-link action files. Persist snapshot hashes and verify action order, selectors, completion and keepScroll against actual capture evidence before declaring prepared. Existing directories are never reused. Source actions are explicit opt-in and may have side effects: do not use form-submit, purchase, login or other destructive selectors. No automatic selector discovery or form submission is added; no network/filesystem sandbox is claimed.
