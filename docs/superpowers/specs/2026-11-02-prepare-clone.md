# One-command source preparation

Continue the approved local, framework-neutral website reconstruction toolkit. Add an opt-in `prepare:clone` command that creates a new workspace using init, captures the authorized source in one explicit browser, validates that the capture matches the request, and derives offline observations. The target URL is a planned route, not an endpoint the command visits. Preserve the initialized editable report and rights ledger. Add a fixed START-HERE.md and local HTML entry point, a preparation state journal and bounded capture logs. No automatic app generation, asset downloads, rights approval, comparison or target/server execution.

Reuse existing URL/path validation, capture collector, observations and process-tree cancellation. Preflight all options before writes; dry-run performs no writes, network or subprocess launch. New destinations only, no overwrite/delete/resume. Preserve partial evidence on error and return a nonzero exit code. A zero child exit alone is insufficient: validate artifact schema, requested source, viewports, engine, state and color scheme. Observations/warnings remain untrusted data and do not become agent instructions. Journal stage results and distinguish prepared from verified. No dependency or lockfile changes. Node >=22.12.0.

Name the script `prepare:clone`, never npm lifecycle `prepare`. Evidence snapshots may contain secrets: users must review before sharing. Browser page code can make its own requests; this is not network isolation. The collector remains read-only apart from existing capture lazy-scroll behavior. Actual Safari/devices/backend and hostile concurrent filesystem mutations remain outside the guarantee.
