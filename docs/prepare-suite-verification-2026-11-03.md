## 구현 범위

기준 main은 `404312e8d3e54a028d55e6c6490f957437604a84`, 실행 검증한 구현은 `bd1abaecc527e25a8db744cd2157a77a5d204d82`다. 이후 검증 기록 커밋은 문서만 변경한다.

`prepare:suite`는 기존 schemaVersion 1 검증 설정을 읽고 명시된 원본 경로·상태를 순서대로 prepare:clone에 전달한다. 모든 동작 파일을 첫 캡처 전에 검증하고 고정 복사본을 만든다. root suite.json은 상대 경로로 동작을 참조하고, 실패·미실행을 포함한 모든 사례와 이후 비교용 임계값·제한 시간을 유지한다. 구현 서버를 실행하거나 대상 페이지를 별도 캡처하지 않는다.

일반 실패 뒤에도 실행하고 --fail-fast나 캡처 중단 시 남은 사례를 not_run으로 남긴다. 원본 설정·동작 복사본의 변경을 검사하고, 최종 무결성 오류가 있으면 개별 사례가 준비됐어도 전체는 failed다. HTML과 JSON에 그 이유를 표시한다. 초기 오류는 쓰기·접속 전에 거부하며 기존 디렉터리 덮어쓰기·삭제·재개는 제공하지 않는다. 앱 생성·권리 승인·기능 동등성을 판정하지 않는다. [사용법](prepare-suite.md)을 참고한다.

기존 예제 HTML/CSS/JS·자산, 독립 스킬, 수집기·비교 계산과 package-lock.json은 변경하지 않았다. 추가 의존성은 없다.

## 세 엔진 실동작

Chromium 151.0.7922.34, Firefox 153.0, WebKit 26.5에서 두 경로·메뉴 상태를 준비했다. 엔진당 2개 사례·3개 화면이며 준비 중 요청 기록에 대상 경로가 없었다. 원래 동작 파일을 빈 배열로 바꾸고 생성한 작업 폴더를 이동한 뒤, 상대 경로 복사본을 쓰는 verify:suite가 세 엔진 모두 완료됐다. 서로 다른 원본·대상 선택자를 실제 실행했고 총 9개 화면 쌍을 비교했다. 이것은 제어된 로컬 HTTP 테스트이지 새 운영 사이트 클론이 아니다.

각 엔진에서 HTTP 503 뒤에 정상 사례를 둔 배치는 failed/prepared를, fail-fast 실행은 failed/not_run을 기록했다. 실패 사례도 suite.json에서 제거하지 않았다. 이 예상 실패의 검출 검사는 통과했다. 실제 취소 범위는 기존 캡처 실행기의 중단 신호 처리와 이번 일괄 스케줄링 검사이며 모든 OS·물리기기의 중단 동작을 증명하지 않는다.

생성한 통합 HTML을 각 엔진의 file://로 열고 390·1440px 화면과 하위 보고서 링크를 확인했다. 실행 스크립트·원격 HTTP 요청이 없고 문서 전체 가로 넘침도 없었다. 넓은 표는 내부 가로 스크롤을 사용한다. Chromium 데스크톱·WebKit 모바일 보고서를 직접 검토했다.
