# 유유랩 홈페이지 재구현

운영 원본: https://uulab.co.kr/ · 구현: 예제 서버의 `/home/` · 관찰일: 2026-11-03.

## 구현 범위

기존 서비스 예제의 같은 Vite 프로젝트 안에 홈페이지를 추가했습니다. `/services/`와 서비스 예제의 기존 `/` 별칭은 유지합니다. `/home/`와 `/services/` 사이의 브랜드·탐색·본문 링크는 로컬로 연결하고 현재 페이지 표시를 구분합니다. 포트폴리오·인사이트·회사소개·문의 등 아직 구현하지 않은 경로는 운영 원본으로 연결합니다.

원본의 아홉 본문 영역(히어로, 소개, 읽기 순서, 설계 결정, 서비스 분야, 성공 사례, 추천 인사이트, 질문 카드, 문의 안내)을 편집 가능한 데이터와 시맨틱 HTML/CSS로 다시 구성했습니다. 홈페이지의 질문 영역은 원본처럼 정적 카드입니다. 서비스 페이지의 FAQ와 달리 아코디언으로 바꾸지 않았습니다.

콘텐츠는 Vite의 HTML 변환 단계에서 생성하며 브라우저 JavaScript 없이도 볼 수 있습니다. 기존 메뉴·Escape/포커스 복귀·테마 저장·스크롤 헤더·진행률·맨 위로 동작을 공유합니다. 저장소 접근을 막아도 테마와 메뉴가 동작하도록 기존 보호를 유지합니다. 새 의존성, 외부 분석·추적 스크립트, 폼 제출 또는 백엔드를 추가하지 않았습니다.

## 실행

```bash
npm ci
npx playwright install chromium firefox webkit
npm run dev
# Vite가 출력한 주소의 /home/ 열기

npm run check
npm run check:browsers -- --out artifacts/home-browser-check

npm run build
npm run preview -- --host 127.0.0.1 --port 4173 --strictPort
# 다른 터미널에서 원본/프로덕션 비교
npm run verify:suite -- --manifest suites/uulab-home.json --out artifacts/home-live
```

원본 `/`와 구현 `/home/`를 매핑합니다. 비교 설정은 기본 화면(1440·768·390px), 모바일 메뉴, 데스크톱·모바일 하단 질문 영역의 총 6개 화면 조건입니다. 특정 허용 차이를 합격 기준으로 주입하지 않습니다. 비교 완료는 시각 승인이나 기능 전체 동등성이 아닙니다.

## 자산과 한계

기존 사례의 로고와 세 프로젝트 PNG를 바꾸지 않고 공유합니다. [자산 기록](assets.json)과 [기존 상세 출처](../uulab-services/assets.json), 저장소의 THIRD_PARTY_NOTICES.md를 함께 확인하세요. 증거 ZIP에는 폰트 파일을 포함하지 않습니다.

프로젝트 수·인사이트 카드·날짜·문구는 관찰일의 스냅샷이며 실시간 집계나 CMS 연동이 아닙니다. 이전 준비 자료와 이번 운영 원본의 소개 문구·인사이트가 달라 새 캡처를 기준으로 작성했습니다. 원본의 지속 애니메이션·카운터 모션은 복제하지 않았습니다. 접근성을 위한 불투명 메뉴와 밝은 다크 모드 아이콘 같은 기존 의도적 차이를 유지합니다. 실제 Safari/휴대폰/터치/백엔드 및 외부 상세 경로는 별도 미검증 범위입니다.

## 경로와 측정 근거

| 원본·상태 | 구현 경로 | 코드·검증 범위 |
| --- | --- | --- |
| `/` 기본 | `/home/` | home-content.js, home-render.js, home.css, home/index.html |
| `/` 모바일 메뉴 | `/home/` | 기존 메뉴 컨트롤 공유, 390×900 캡처 |

| `/services/` 및 기존 `/` | 기존 경로 유지 | 공통 탐색의 홈 링크만 로컬 연결, 서비스 전용 스타일·동작 유지 |

신규 화면의 본문 최대 폭은 1280px, 좌우 여백 24px이며 실제 원본 DOM과 계산 스타일을 확인했습니다. 본문 섹션의 기본/큰 화면 여백, 카드 열 수, 글꼴 크기와 줄 높이를 반응형 CSS로 구현했습니다. 캡처는 1440·768·390px, 동작/가로 넘침 검사는 320·390·768·1440px를 사용했습니다. 원본 전체 문서를 캡처해 하단까지 시각 검토했으며 메인 시작 화면만 만든 사례가 아닙니다.

전체 `npm run check`는 도구·Chromium 검사 625개, 안전한 빌드 출력 검사 7개, 프로덕션 예제 검사 10개, **642개 통과**입니다. 스킬 검사와 프로덕션 빌드도 성공했습니다. `check:browsers`는 Chromium·Firefox·WebKit 각각 **50/50 통과**입니다. 모든 실행의 실패·취소·건너뜀·todo는 0개입니다. 각 엔진의 50개는 동일 검사를 반복한 것이며 일부가 전체 검사와 겹치므로 추가 고유 검사 수로 합산하지 않습니다.

홈페이지 추가 검사 20개는 렌더링/공통 아이콘 8개, 실제 HTTP 동작 10개, 계산 스타일 2개입니다. HTTP 검사는 전체 콘텐츠와 이미지, 가로 넘침, JavaScript 미사용, 페이지 왕복, 테마 저장·차단, 메뉴 Escape/포커스, 창 크기 변경과 맨 위로 키보드 조작을 확인합니다. 두 계산 스타일 검사는 setContent 기반 계약 검사이며 HTTP/프로덕션 검사를 대신하지 않습니다. 실제 원본·프로덕션 시각 비교는 아래 Chromium 실행으로 구분합니다.

로컬 부분 snapshot에는 npm 의존성과 글꼴이 없고 로컬 HTTP 탐색이 차단되어 있습니다. 로컬 결과는 오프라인 렌더링 검사와 in-memory 스타일 진단에 한정했으며 전체 게이트는 완전한 Actions checkout에서 실행했습니다. 초기 렌더링 검사 6개 중 5개 실패·1개 통과를 확인하고 구현했습니다. 브라우저 게이트 연결, 행간·화살표 간격, 공유 아이콘 경로도 각각 실패 재현 후 수정했습니다. 마지막 입력/CI 파일 대조가 아이콘 경로의 문자 차이를 발견했으며 원래 경로 복구와 해시 회귀 검사를 추가했습니다.
